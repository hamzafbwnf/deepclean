# DEEPCLEAN Project Instructions

## Canonical game design document

- The canonical living design document is `Docs/DEEPCLEAN_GDD.md`.
- Read the relevant sections of that document before making gameplay, progression, narrative, level-design, UI, or art-direction decisions.
- If a requested implementation conflicts with the canonical GDD, point out the conflict before proceeding. The user's latest explicit decision takes precedence.

## GDD edit ownership

- Treat `Docs/DEEPCLEAN_GDD.md` as read-only in ordinary implementation, review, research, and brainstorming chats.
- Do not edit the canonical GDD merely because a feature was implemented, discussed, or proposed.
- Edit it only when the user explicitly identifies the current conversation as the dedicated canonical GDD-maintenance conversation and asks for a GDD update.
- Other conversations may propose changes, but those proposals remain non-canonical until incorporated by the designated GDD-maintenance conversation.
- Preserve the document's decision-status labels and changelog whenever it is updated.
